# ADR-0001: 単一 :app モジュールの維持

- 状態: Accepted
- 日付: 2026-10-12
- 関連: NFR-001, NFR-002, REQ-001

## コンテキスト
本アプリは単一画面の使い方説明（UsageScreen）と、オーバーレイ表示する単一 FAB（FloatingStopwatch）、タイルサービス（TileService）、およびこれらを管理するサービスからなるコンパクトなアプリケーションである。
マルチモジュール構成（`:core:model`, `:core:data`, `:feature:overlay` 等）に分割するか、単一 `:app` モジュールを維持するかを決定する必要がある。

## 選択肢
1. **マルチモジュール構成への分割**:
   - 利点: モジュール間の境界が厳格化され、並列ビルドの向上が見込める。
   - 欠点: 画面が 1 つ・サービスが 1 つの規模に対して Gradle 設定や依存関係の保守オーバーヘッドが過大になる。
2. **単一 `:app` モジュール**:
   - 利点: 構造がシンプルで理解しやすく、ビルドスクリプトや CI の保守性が高い。パッケージ構成（`ui/`, `domain/`, `data/`, `service/`）による関心事の分離で十分対応可能。
   - 欠点: モジュール間の境界をビルドシステムによって強制できない。

## 決定
単一 `:app` モジュール構成を維持する。

## 結果
- 新たなモジュール追加は行わず、`:app` 内の明確なパッケージ分離によってレイヤ責務を担保する。
- 将来的に機能が大幅に拡張された場合に再評価を行う。
